## 4. 并发测试（秒杀不超卖）

**验证目标**：多用户同时抢购，库存不超卖、不重复下单、异步落库、卖完自动下架。

**方法**：准备 5 个用户（id 2~6），重置库存后，用 `xargs -P 5` 并发请求 `/order/seckill/4`。

**实测结果**（商品 4 当前库存为 4，5 个用户并发抢）：

| 用户 | 结果 |
|---|---|
| 用户2 | ✅ 抢购成功 |
| 用户3 | ✅ 抢购成功 |
| 用户4 | ✅ 抢购成功 |
| 用户5 | ✅ 抢购成功 |
| 用户6 | ❌ 手慢了，库存不足 |

**最终状态**：
- Redis 库存 `seckill:stock:4` = **0**（4 个库存被 4 个用户抢完，第 5 个被拒）
- 下单去重标记成员数 = **4**（不重复下单）
- 数据库订单 `tb_order`（goods_id=4）= **5 条**，买家恰好 1,2,3,4,5 各一条
- 机械键盘 `stock=0, status=2`，**卖完自动下架**

**结论**：Lua 脚本在 Redis 内原子完成"查库存 + 去重 + 扣库存"，**不超卖、不重复下单**；扣减后才发消息异步落库（削峰）；库存耗尽自动下架。建议使用 JMeter 以 100~500 并发复测极限压力表现。

## 5. 缺陷记录与修复

| 编号 | 缺陷 | 严重性 | 状态 |
|---|---|---|---|
| B-01 | Spring Data Redis 3.x API 包路径变化导致编译失败（GeoResults/BitFieldSubCommands） | 高 | ✅ 已修复 |
| B-02 | 签到连续天数位序错误（BITFIELD 返回值 bit0=今天，高位往回数导致首日显示 0） | 中 | ✅ 已修复 |
